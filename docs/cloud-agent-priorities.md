# Lester 的云端 Agent 优先级

2026-10-15。基于当前仓库的执行器、PostgreSQL 状态、沙盒监督进程与工作区交互检查。

云端体验的基本承诺是：离开页面后任务仍有明确归宿，需要用户时能找到入口，回来时能看清实际发生了什么。本轮选择以下三个可验证的目标。

| 目标 | 原有缺口 | 交付行为 | 验证方式 |
| --- | --- | --- | --- |
| 任务状态自动收敛 | 没有排队输入的孤立运行可能要等用户访问才核对 | 启动即扫描，之后每 15 秒分页核对；有执行锁的远端副本不受影响；真正失去执行者的任务结束为中断/取消，待答请求撤销 | 真实 PostgreSQL 测试：模拟另一副本持锁、遗留写入、未完成模型请求、取消中任务、重复扫描 |
| 跨会话找到待处理事项 | 需要逐一打开会话找计划、权限和问题 | 侧栏任务面板、待处理计数、最近任务筛选与稳定分页，单列 Agent 回复后仍活跃或未知的后台命令，打开原会话处理并保留草稿 | 浏览器验证筛选、加载更多、Escape/焦点、错误重试、打开会话、草稿与请求次数；数据库验证租户隔离与历史任务取舍 |
| 耗时和模型用量有来源 | 用量已持久化但用户没有查看入口 | 按需展开统计；实测、估算、缺失分别呈现；缓存只计一次，包含整理上下文的请求，不编造费用 | 不同缓存语义、缺失输出、报告零输出、进行中请求、无请求、越权读取的集成测试 |

## 执行与安全边界

执行器仍在 API 内。关闭浏览器不会停止正常任务，API 重启仍会中断运行。监控器检查执行锁而非按超时猜测存活；不接管一个仍持锁的执行者，不根据相同文件内容猜测先前工具成功，也不重放命令来恢复结果。恢复继续使用当前会话的显式新任务，已有权限与精确版本的 Plan 审批仍独立执行。

任务面板只读，不在列表里批量批准、自动重试或公开成果。只展示每个会话的最近任务，完整历史留在会话记录中。成果数是已登记元数据，不是内容验收或当前文件存在性的证明。耗时包括等待用户、模型和工具的时间；用量是已观察数据，不是货币账单或强制预算。

新增接口不暴露模型请求正文、密钥、原始用量映射或其他工作区的数据。查询使用 migration 026 的最新任务、活跃运行、最近事件、待答请求与活跃后台命令索引；升级前先备份、停止写入并应用迁移，不删除数据卷。

## 更大规模部署的后续条件

独立 Worker、进程崩溃后自动续跑、周期调度、计费与预算强制执行不属于本轮已交付能力。它们需要单独的持久任务认领、租约/栅栏、可确认副作用边界、资源配额与迁移验证；不能仅换一个进程或重放工具就宣称实现。现阶段先用本轮的数据与状态能力观察实际并发、等待、失败和请求消耗，再决定下一步拆分与配额策略。Lester 继续围绕会话和成果组织，不引入 Workflow/DAG 编辑器、自动 Memory 或额外浏览器产品。
