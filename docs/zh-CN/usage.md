## 持续陪伴的个人助理

固定的 **Lester** 入口（宽屏右下角、窄屏导航栏）打开独立、常驻的个人助理面板。切换项目、会话或设置，以及收起再打开，都保留聊天和草稿。`/app` 仍是任务首页，任务输入框不再混入个人助理模式。个人助理负责记忆和任务调度，不具备命令、文件、浏览器、Skill 或审批工具。需要实际执行时，它创建独立任务，或继续你之前的会话；任务入口保留在 `/app`、`/app/new` 和各项目中。

记忆分为个人偏好、项目认知、工作脉络，按用户和工作区隔离，项目事实仅带入对应项目。记忆面板支持查看来源、搜索、编辑、忘记和撤销，自动提炼会显示可撤销提示，也可关闭。更正和忘记会阻止旧聊天重新提炼出被移除的信息；原聊天与已接受任务的记忆快照仍保留。

重新打开助理会读取最新聊天和记忆，并保留未发送草稿。记忆搜索提供无结果提示，短屏编辑时可完整滚动。账户菜单支持方向键、Home/End 和 Esc；从任务或项目进入设置、切换设置栏目后，仍可返回原位置。

任务卡沿用实时任务状态和工作区 SSE。新委派使用默认权限，续接保留原 Agent、模型和项目，运行中默认排队。个人助理不能打断、审批或提高任务权限；网络异常按原始回执检查，不会自动重发任务。

已有部署先备份、停止 API 写入与活跃任务，补齐 001–030 后执行 `000031_personal_assistant.up.sql`，再同时重建 API 和 Web。新 Compose 数据库初始化 001–036；Helm 需外部执行 SQL。回滚 031 会删除个人对话、记忆和委派回执，保留具体任务会话、文件和执行结果。当前是有边界的词语/CJK 检索，无向量库、全历史自动导入或后台推送。

## Lester 能做什么

- 使用邮箱和密码注册、登录，自动创建个人 Workspace
- 左下角账户菜单统一进入个人资料、模型、Computer 和 Skill 设置；称呼与内置头像主题可持久化修改
- 在 Workspace 中配置自己的模型 Provider 和密钥
- 支持 OpenAI、Anthropic、Azure OpenAI、OpenAI-compatible、AWS Bedrock、Google Vertex AI 和 Microsoft Foundry
- 通过 Workspace 级 SSE 实时输出 Agent 回复和当前思考/工具活动；刷新后按持久化事件游标无重复续流，左侧会话栏仅在会话运行或正在停止时展示状态，并用一次性未读提示告知后台任务完成或失败；运行区展示当前动作和耗时，发送键在运行期间变为停止键，可随时终止当前任务
- 完整保存中间回复、工具调用与工具结果；模型请求按完整 ToolExchange 管理工作集，默认保留最近 10 次工具交互
- 单次任务不限制模型/工具循环次数；运行会持续到模型完成、发生明确错误或运行上下文被取消
- 无需选择 Agent，首页直接输入目标即可开始；默认使用 Lester 和已配置的默认模型，也可切换模型、添加附件。首页围绕 760px 输入区组织内容，小屏自适应；Agent 选择与“试试一个任务”按需展开，示例只填草稿。顶部教学与已发布站点使用带名称和提示的轻量图标；桌面项目/会话操作在悬停或键盘焦点时出现，触屏始终可见。点击“新对话”只返回输入页，不提前创建空会话。旧会话保留原角色以兼容已有历史。
- 为每个用户分配一个 Computer（本地 Docker 或阿里云 ACS Agent Sandbox），并以 `/workspace/conversations/{conversationId}` 隔离会话目录
- Agent 可以在 Computer 中执行命令、读写文件和使用终端
- 终端连接真实交互式 Bash PTY，支持 Tab 命令/路径补全、↑↓ 历史与前缀查找、Ctrl+R 历史搜索、Ctrl+C 中断、Ctrl+L 清屏和窗口尺寸同步；多行粘贴等待 Enter 执行。选择内容后可用工具栏、Ctrl+Shift+C / ⌘C 复制，Shift+Esc 离开终端焦点。手机提供 Tab、历史、Esc、Ctrl+C 和 Ctrl+D 按钮；断线可重连，但会启动新 Shell，不恢复正在运行的进程。
- 命令历史保存在各会话的 `.agent/terminal/bash_history`，属于 Computer 私有数据；敏感命令以空格开头可避免记录。自定义镜像未装 Bash 时会提示并回退到 `sh`。提供的 `backend/Dockerfile.sandbox-runtime` 已包含 `bash-completion`、`less` 和终端定义；命令参数补全依赖相应工具的补全脚本。现有包含 Bash 的 Computer 更新 Web 与 Sandbox Service 即可获得行编辑支持；新增镜像包需重建运行时镜像及 ACS 模板 / 新 Computer，不要删除已有工作区来升级。
- 右侧 Files 提供类似 VS Code 的目录树与文件预览，支持代码/文本行号、图片、PDF，以及受限 iframe 中的 HTML 页面预览、源码切换和独立页面打开；桌面端可拖动调整右侧面板宽度，并可收起左侧会话栏
- 任务开始时聚焦对话，第一份文件出现后展开更宽的预览并收起目录；桌面顶部“工作区”打开或收起面板，成果与文件在面板内切换；手机保留直接查看成果的入口。聊天区以简短成果入口连接右侧详细验收界面。后台文件更新会刷新或新增标签，保留正在浏览的文件与主动关闭的面板状态。终端、技能与已创建 Agent 的配置收纳在面板的“工具”菜单。手机和放大预览使用原生模态对话框，关闭后恢复焦点，支持嵌套部署确认。
- 首页发送时，输入框平滑移到底部并接续到对话页；创建失败会回到居中位置并保留草稿。动画遵循系统的减少动态效果偏好，不延迟或重试任务请求。
- 新任务页在输入为空时显示三个短示例，已有草稿或附件时收进折叠入口，选择示例只填写草稿；同时提供轻量入场、聚焦反馈。会话选项在桌面和手机上均以独立浮层展开，不挤压布局。官网以小型网页、文档、代码预览展示成果示意，关闭 JavaScript 也能切换。减少动态效果偏好会跳过动画。
- 文件工作区支持最多 8 个打开标签、Markdown 预览/源码、下载、放大预览和窄屏文件面板。聊天下方的任务文件卡片在本轮输出结束（或失败、停止）后才展示已确认存在的当前文件，生成期间不占据回复底部；右侧文件列表和预览仍实时更新。“让 Agent 修改此文件”会给输入框添加可移除的文件引用，发送时只附相对路径提示，不自动注入文件内容。
- 会话栏支持按标题搜索；文件目录按内容占用高度，变化列表按需展开。专注预览可暂时收起目录，预览/源码与文件操作集中在同一工具栏，为内容留出更多空间。
- 切换会话和刷新页面会恢复草稿、文件引用、打开标签、预览/源码模式、目录展开状态及聊天/源码阅读位置。状态按用户、工作区和会话保存在当前浏览器标签页中，最多保留 50 个会话，持久化草稿最多 100,000 字符；退出登录会清除。尚未上传的本地附件仅在页面内切换时保留，刷新后明确提示重新选择，不会保存文件内容到浏览器存储。
- 阅读历史时不会被流式输出强制拉到底部，有新输出时可一键跳转。运行状态使用真实工具事件和耗时，工具参数/输出默认折叠；运行中可以先写下一条草稿，但不会并发发送。源码更新保留阅读位置，文件更新不抢走当前预览；HTML 自动刷新仍可能重置页面内部交互状态，不放宽 iframe 安全限制。
- 文件列表在文件操作及工具/任务结束事件后自动同步；页面可见时，运行中每 5 秒、空闲每 15 秒检查文件元数据，覆盖 bash 和后台脚本的变更。扫描最多 64 个目录、2000 个文件、5 层子目录，默认跳过依赖、缓存和 `.agent` 目录（仍可手动展开）；超出或读取不完整时显示提示。轻量变化列表合并本轮持久化文件事件与本次打开期间检测到的增删改，不是完整文件历史、内容 Diff 或 Checkpoint；同大小且同修改时间的内容变化无法靠元数据识别。
- Computer 空闲后自动暂停并在下次访问时恢复；服务会持续校验真实状态，Docker 使用用户级 Volume，ACS 使用云端 Sandbox 暂停/唤醒
- 内置 Skill 广场，并支持把 Skill 安装到当前会话的 `.agent/skills` 后按需加载
- 支持会话附件上传和在聊天框直接粘贴图片；文件只写入 `.agent/upload`，模型默认只接收文件路径提示，不会自动注入文件内容

## 项目官网与帮助文档

根路径 `/` 为极简公开官网，以居中的“想清楚。做出来。”、一个主要按钮和简短介绍呈现产品定位，并说明名字来自 GTA V 中冷静、机敏的幕后黑客 Lester Crest。通过轻量导航保留工作区、帮助文档、实际 GitHub 仓库和问题反馈入口。`/docs` 为站内帮助文档，包含快速开始、使用指南、模型配置、部署与升级及常见问题。官网、完整帮助正文、工作区、登录、设置和逐步教学支持中文、英文、日文、韩文、法文与西班牙文。官网和文档按请求渲染所选语言，无需登录或访问 API，禁用 JavaScript 也可阅读；工作区保留在 `/app`，登录页和账户菜单提供官网/帮助入口。

站内文档内容位于 `frontend/src/lib/site-docs.tsx`。修改产品能力、环境变量或迁移要求时同步更新。进入工作区沿用现有登录流程，不会自动发送任务；本次官网无需新增数据库迁移或部署服务。已有部署需重建 Web 容器并刷新页面才能看到新版首页。

首次访问跟随浏览器语言，不支持的语言回退英文。官网导航、登录页、账户菜单和设置侧栏可手动选择；浏览器 Cookie 记忆一年。紧凑菜单包含本地 SVG 国旗、原文语言名称和选中标记，支持方向键、Home/End、Enter 与 Esc；统一的 Lester SVG 标志同步用于网站图标。切换语言保留草稿与导航过程中的本地附件。用户消息、自定义项目/Agent 名称、模型回复、文件内容及部署命令保持原样。

## 逐步新手引导

新账户首次进入工作区会看到 7 步入门教学，可随时选择“稍后再学”。工作区顶部、账户菜单和设置页的“新手引导”可以重新打开教学中心，包含首次任务、模型、项目、文件成果、Agent、上下文库、Computer、Skill、个人资料和产物发布，共 10 类教学。功能页首次访问会显示可关闭的教学提示。进度按账户和主题保存，换设备也可继续，完成后可重新看一遍；已有账户升级后不强制弹出欢迎教学。

引导只解释界面，不会自动发送任务、调用模型、安装 Skill 或发布文件。打开模型配置时，已有任务草稿继续保留。完成模型教学不代表模型服务已验证；仍需一次真实运行确认。

已有数据库完成 001–013 后，先备份，再执行一次 014、015 并重建 API/Web：

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yaml stop api
docker compose --env-file deploy/.env -f deploy/docker-compose.yaml exec -T postgres \
  sh -c 'psql -v ON_ERROR_STOP=1 --single-transaction -U "$POSTGRES_USER" -d "$POSTGRES_DB"' \
  < backend/migrations/000014_user_guides.up.sql
docker compose --env-file deploy/.env -f deploy/docker-compose.yaml exec -T postgres \
  sh -c 'psql -v ON_ERROR_STOP=1 --single-transaction -U "$POSTGRES_USER" -d "$POSTGRES_DB"' \
  < backend/migrations/000015_rotating_tokens.up.sql
for migration in 000016_run_submissions 000017_model_budget 000018_command_tasks 000019_model_request_usage 000020_context_checkpoints 000021_run_interactions 000022_run_inputs 000023_file_changes 000024_project_rules 000025_run_permissions 000026_cloud_task_indexes 000027_automations 000028_permission_reviews 000029_conversational_schedules 000030_native_signin; do
  docker compose --env-file deploy/.env -f deploy/docker-compose.yaml exec -T postgres sh -c 'psql -v ON_ERROR_STOP=1 --single-transaction -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < "backend/migrations/${migration}.up.sql" || exit 1
done
docker compose --env-file deploy/.env -f deploy/docker-compose.yaml up -d --build api web
```

保留原 `.env`、加密密钥与数据卷；更早的部署先按编号补齐缺失迁移。全新 Compose 卷包含 014、015；Helm 在部署前手动应用 SQL。014 回滚只移除教学进度，需配套恢复兼容的 API/Web。进度接口限定当前登录用户，不能读写其他账户的进度。

## 定时任务与入站 Webhook

从账户菜单的“自动任务”或任务状态面板的“管理自动任务”进入。选择项目、模型、Agent、任务内容和权限，支持单次、每天、每周及指定 IANA 时区的五段 Cron。新建默认不启用，勾选后才定时触发；重复任务跟随时区和夏令时，单次时间按浏览器本地时间保存。服务约每十秒检查一次持久化触发，每次执行创建独立会话。“立即运行”是明确的手动触发，即使日程暂停也可使用。

前一次任务、待答请求或运行中/状态未确认的后台命令尚未结束时，定时触发会跳过并记录；Webhook 和手动事件按接收顺序等待。停机期间错过的周期合并为一次，不集中补跑全部历史。暂停或删除取消未开始的事件，已在派发的任务需在会话中停止。触发时保存任务配置快照，正常会话受理时保存项目规则和 Agent 资源；执行前复核账户、工作区与模型权限。默认权限可能等待确认，自动审批和完全访问需主动选择，范围仍限于已授权 Computer。

选择“Webhook 触发”可获得通用接收地址及一次性展示的独立密钥。发送方安全配置 `LESTER_WEBHOOK_SECRET`，生产使用 HTTPS：

```bash
curl -X POST 'https://lester.example/api/v1/hooks/<automation-id>' \
  -H "Authorization: Bearer $LESTER_WEBHOOK_SECRET" \
  -H 'X-Lester-Event-ID: issue-123-created' \
  -H 'Content-Type: application/json' \
  -d '{"issue":123}'
```

请求体为不超过 32 KiB 的 JSON 对象，只提供任务数据，不能更改权限、工作区、模型或引用。同一事件 ID、相同规范化数据返回原记录，数据变化则拒绝；重复投递不新增任务。服务端只存密钥哈希，创建或重置时展示一次，重置后旧密钥失效。Cookie 和 URL 参数不能认证 Webhook。每个账户最多 100 个定义，每个定义每分钟最多 30 个新手动/Webhook 事件及 20 个待触发事件；重复事件不占新额度。记录展示最近 20 次触发和真实会话入口，启动结果不明时只查原回执，不自动重跑。本次为入站接口，不包含外发回调和 GitHub 等应用的原生协议适配。

已有数据库需备份、停止 API 写入与活跃任务，按编号执行尚未应用的迁移至 `000029_conversational_schedules.up.sql`（含 027–029），同步重建 API 与 Web。新 Compose 初始化 001–036，包括此前缺失的 016–026。不要删除数据卷。回滚 027 删除自动任务及触发记录，保留会话、文件与已发生的操作。调度器和执行器仍在 API 内，API 崩溃后不会自动续跑旧工具。[行为、API 与恢复说明](../automations-and-questions.md)。

也可以直接在会话中说：**“每周一上午九点，在产品项目生成一份评审清单。”** Lester 使用原生 `list_schedules` / `propose_schedule` 工具，在聊天框上方展示简洁的确认卡：时间、时区、项目、下次触发，以及可展开的任务、模型和权限配置。确认后才创建、修改、暂停或恢复任务，拒绝或要求调整均不生效。新任务沿用当前任务模型与 Agent，默认使用默认权限；修改保留原模型、Agent 和权限。浏览器发送时保存的时区仅供参考，用户明确指定的时区优先，信息不足时先询问。每次触发在独立会话中使用保存的任务内容，不继承原会话历史、文件、附件或 @ 引用。

确认回执和配置在同一个数据库事务提交；旧版本或已过期的触发时间需要重新提出配置，响应丢失时只查询原回执，不自动重复发送。确认定时任务不批准 Plan，也不扩大工具权限。无需安装 Skill；Skill 可以复用工作方法，时间与持久化仍由服务端调度器负责。升级需先执行 **029**；存在定时任务交互记录时回滚会拒绝，归档回执也不会撤销已经应用的配置或任务。

结构化问题固定在聊天框上方，支持 1–3 题、单选/多选、推荐标记、同时保留补充文字、键盘操作及多题提交前核对。推荐项不默认选中，回答草稿刷新后保留，提交不批准 Plan 或工具；已提交回答在会话回执中查看，停止键和原聊天草稿始终可用。

## 问题澄清与 Plan 审阅

输入区不再要求用户选择执行模式。复杂的多文件改造、架构工作或需要比较方案的任务，由 Agent 判断是否先调用 `enter_plan_mode`，再只读检查、查看目录和澄清要求；简单明确的任务可直接执行。判断由模型完成，不用字数阈值强制触发。兼容已有 API 客户端显式请求 Plan。服务端拦住命令、文件修改、发布及其他变更，工具别名和自定义工具也不能绕过。用户主动上传附件、安装 Skill 属于独立操作。计划可批准、提出调整或暂不执行；批准绑定当前活跃 run 中保存的准确参数和版本。上下文压缩后从平台记录补回批准范围，正常执行模式不重复请求 Plan 批准。

结构化问题用于收集信息，与批准分开。回答草稿随会话保存，切换或刷新可继续。已受理回答可幂等重试；提交结果不确定时按原请求查询，不自动重发。取消或失败撤销待答请求；刷新会核对跨 API 的 session guard，执行者丢失时标记中断，旧回答不能重新启动。运行中调整和明确排队下一任务仍是后续目标。

已完成 001–020 的数据库，备份并停止 API 写入后只执行一次 `000021_run_interactions.up.sql`；已完成 001–019 的数据库补齐 020、021，不重复旧迁移。回滚 021 前先停止相关活跃任务并配套兼容 API/Web，原始消息和文件保留。

## 任务权限

输入框支持默认权限、自动审批、完全访问三档，与 Plan 独立。默认自动读取普通文件，修改文件和执行命令需确认；自动审批允许普通会话文件操作和极少量版本查询命令，敏感路径及其他命令仍需确认；完全访问仅在已授权 Computer 内免逐次审批，不会获得宿主机权限或覆盖账号、网络、Plan 和文件安全限制。

审批卡片贴在输入框上方。允许一次绑定当前任务、真实工具调用和参数摘要，批准后消费，不能重放；本次任务允许只覆盖同一任务中的普通写入／编辑。命令和敏感路径只允许逐次审批。切换选项仅用于下一任务，排队时会保存权限，展开队列消息可查看。停止、任务中断或补充当前任务要求会撤销待处理审批；审批回执不代表操作已经成功。

已有 024 版本数据库需备份、停止任务和 API 写入，应用 `backend/migrations/000025_run_permissions.up.sql`，同时重建 API 和 Web。新 Compose 数据库自动包含迁移。升级不会删除数据卷；回退需要兼容版本，不会撤销文件或外部操作。

## 会话回顾与上下文概览

已有会话支持「会话回顾」与本地 `/recap` 命令：摘录最近目标、最近回复（最多 400 个 Unicode 字符），展示已观察的状态与文件更新入口。回顾不调用模型，不代替原始记录，不推断测试通过，也不批准或重放操作。离开至少两分钟且有新进展时，可自动展开回顾；未发送文字、附件或引用会阻止自动展开。可在回顾中关闭此会话的自动回顾，偏好与离开标记按账号、工作区、会话隔离，退出登录时清除。

「上下文概览」区分最近用户消息已受理的材料快照和待发送材料，项目规则保留版本。引用不代表已经读取或加载，实际执行见工具记录；这里不是完整模型请求或精确 token 计数。简洁过程合并连续三次及以上已确认完成的工具操作，详细过程保留各条记录。失败与未知结果不会归入成功分组。失败、停止后的继续或重试仅将指令加入草稿，确认发送后才按所选权限启动新任务。

## 输入区与主动规划

输入框的「＋」统一提供附件、@ 引用（上下文、会话、Skill）和 Agent 选择；直接输入 `@`、粘贴图片仍可用。模型选择位于右侧圆形发送按钮旁，权限保持独立可见。新任务与排队任务默认正常开始，由 Agent 分别判断是否先规划；正在运行时锁定模型，结束后才可切换。主动规划需要 API 与 Web 同步升级，不需要新增数据库迁移，但必须先应用已有迁移。

## 云端任务、后台核对与用量

侧栏的「云端任务」展示每个会话的最近任务，可筛选全部、进行中、需处理和已结束，查看排队/暂缓数量及已登记成果，再打开原会话审阅或恢复。Agent 回复完成后仍在运行的后台命令会单独列出；状态未知的命令归入需处理，后台命令未结束时不会出现在已结束筛选中。数据按工作区隔离，从 PostgreSQL 读取，与打开了哪些标签页无关。默认每页 20 项、最多 50 项，使用稳定游标分页；第一页在页面可见时轮询并复用现有工作区事件，不新建 SSE；加载更多页后可点击刷新回到最新页。查看任务不会发送消息、批准操作或恢复执行；文件后台到达时仍登记标签，但不会盖住弹窗或已展开的文件修改审阅。加载失败显示错误，不冒充空列表。「已完成」只表示运行结束，不代表验收或测试通过；成果数量仅为登记元数据，不是当前文件已验证的快照。

API 在启动时及之后每 15 秒扫描一批最多 30 个活跃会话，通过现有 PostgreSQL 会话级锁核对执行者，兼容多个 API 副本。不会因为任务耗时长或暂时没输出而中断任务。执行者已消失时，运行记为中断失败，取消中的运行完成取消；缺失工具结果保持未知，待答问题/审批撤销，后续队列暂缓，不自动重跑工具。关闭浏览器不会取消正常执行，但重启 API 仍会中断进程内执行；检查当前结果后显式创建恢复任务，不承诺崩溃后透明续跑。

展开「耗时与模型用量」可看含等待的总耗时、请求数、服务商已报告的输入/输出，以及未报告输入的独立估算。兼容不同服务商的缓存计数，缓存只计一次，包含上下文整理请求。输出用量缺失保持未知，真实报告的零保留为零；不推算费用或宣称账单金额。接口为 `GET /api/v1/tasks` 和 `GET /api/v1/conversations/{id}/runs/{runID}/usage`，不会返回提示词、密钥或服务商原始计数映射。

已有数据库到 025 的部署：备份数据库、停止 API 写入与活跃任务，执行一次 `backend/migrations/000026_cloud_task_indexes.up.sql`，同步重建 API 与 Web。026 只增加查询索引，不改任务与文件数据；全新 Compose 自动初始化。回滚只删除索引，不要删除数据卷。[云端 Agent 优先级与边界](../cloud-agent-priorities.md) 记录了本轮的三个交付目标。
